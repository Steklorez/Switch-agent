Hard rules this template exists to honour: * The raw, serial-bearing device_id NEVER appears here -- not as text, not as an attribute value, not in a URL. The page is addressed by mtp.windows.device_fingerprint() and device_detail.js resolves that fingerprint back to the raw id server-side, at action time, via GET /api/devices/by-fingerprint/{fingerprint}, purely so it can call the EXISTING rename/storage-mapping endpoints unchanged. * The activity section is titled "SwitchAgent activity" and is never called "Installed games". SwitchAgent can only ever prove what it attempted and transferred, never what the console ended up with. * There is no remote-delete action here, by design -- SwitchAgent never deletes anything from the console itself, on any page. Forgetting a device (dropping SwitchAgent's OWN record of a Switch it has seen -- never the console's content) is a different action and lives on the /devices list page, where the stale rows are actually visible -- see web/services.py's forget_device(). #} {% block content %}
